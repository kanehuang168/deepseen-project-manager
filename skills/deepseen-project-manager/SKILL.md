# DeepSeen 项目管理

把多步骤工作推进到用户能检查的结果，支持交接、中断恢复和有证据的复盘。适用于创作、运营、研究与软件项目；单步小任务直接完成，不强制建大计划。这个Skill提供方法，不会凭空创建云端员工、调度器、后台任务或费用授权。

## 从结果到执行

先明确要交付什么、什么现象算完成、哪些不在范围内；已有信息直接复用，只有答案会改变预算、风险或验收时才澄清。把必要步骤、依赖、输入、负责人/当前宿主、产物和完成证据连起来，优先推进可独立完成的工作。

执行前核对实际可用工具和授权。不存在的员工、接口、预算、计划任务不能写成已经存在；只有当前宿主允许且任务获准时才委派，不默认多智能体。跨聊天消息、付费、公开发布或不可逆动作按当前授权执行，不因为切换工具反复询问已有批准。

根因不清、反复失败或涉及多种方案时，可按需交DeepSeen深知灼见形成最小计划；没有该技能也可在本任务内完成规划。只要建议时不擅自执行变更。

## 交接、恢复与堵塞

只给接手者当前步骤的目标、必要材料、有效事实、未知、预算和完成标准，不转发全部聊天。优先引用用户已有项目/任务/文件，不另建第二套事实源；没有系统时用简单清单即可。结构见[交接与恢复](references/handoff.md)。

恢复时检查有效产物、当前版本、已受理任务和授权剩余范围。已完成且有效的步骤不重复；供应商状态不明先查原编号，不重复收费提交。保留成功片段和无关修改；需要返修时返回归属步骤，缺关键输入只暂停依赖它的动作。

## 验收与交付

逐项核对用户目标，再检查组合后是否真的可用。区分执行完成、产物检查、实际运行、部署和用户验收。文件存在不等于内容正确，子任务通过不等于整体完成；未覆盖项保留，不因报告时间到了而宣布修好。

给用户可见的“已完成、证据、未完成与阻碍、下一步”。用户明确要求的定期报告必须实际交付；文件落盘不是发送完成，调度未配置也不能声称自动运行。示例见[虚构项目](assets/cup-project.md)。

复盘只记录有证据的事实、假设与动作，检查上次动作是否落实；单次满意不自动升级通用Skill。方法吸收可按需交DeepSeen吸星大法，但不自动改官方记忆、生产服务或公开发布。
